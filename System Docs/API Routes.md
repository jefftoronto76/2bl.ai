# API Routes

## API Routes

Admin routes all call `getAuthContext()` first and scope Supabase
queries by `tenant_id`. Public routes resolve tenant via the Host
header. The prompt + blocks routes below are **thin consumers** of the
`services/prompt/` service (see `System Docs/Utilities/Prompt.md`) — they own
auth, validation, and response mapping; the data-access and business logic live in the service.

### Prompt compilation

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/prompt/compile` | POST | Compiles all active blocks for the resolved tenant into the master prompt — tenant is resolved via `resolveTenantForPromptSet(prompt_set_id, authCtx, isPlatformAdmin)` (July 2026), not blindly `authCtx.tenant_id`, so a platform admin publishing a composer-family set gets the SBL tenant regardless of their own session tenant (403 for a non-admin targeting a composer set). Orders by compile sequence (identity → knowledge → guardrail → process → output_format); within each type, blocks with `order > 0` come first ascending by order, then blocks with `order` = 0 or null come last ordered by title ascending. Logs the final compile sequence (title, type, order) before joining. Joins bodies with double newlines. **Requires `note` in the body** (July 2026 — `{ summary, why?, changed_block_ids? }`; validated server-side by `parseNote`, `services/prompt/release-note.ts` — 400 `{ error: 'A release summary is required.' }` when missing/invalid/over 72 chars). Archives the previous `compiled_prompts` row (content + its own release-note fields) to `compiled_prompts_history` and increments the version, writing the new `note` onto the row. **Unconditionally activates** (July 2026, single-live-per-type — see `System Docs/Utilities/Prompt.md`'s `compile.ts` row): clears any other row/set live for the same `(tenant_id, prompt_type_id)` slot in both `compiled_prompts` and `prompt_sets`, then marks the new compiled row and the target `prompt_set` both `status='live'`. 404 when `prompt_set_id` doesn't resolve to a set in this tenant; 409 (friendly message) on an activation race caught by the partial unique index. Returns `{ success, version, tokenCount, content, updatedAt }`. |
| `/api/admin/prompt/compile/check` | POST | LLM-based safety review of a single block body. Takes `{ body: string }`, returns `{ ok: boolean, issues: [{ description: string, offendingText: string \| null }] }`. Server-side verbatim guard: every returned `offendingText` is validated against `body.includes()` and nulled if not a real substring. Fails open to `{ ok: true, issues: [] }` on any error so the save flow is never blocked. |
| `/api/admin/prompt/save` | POST | Manual save path for the master prompt (legacy). Takes `{ prompt, checkResult }`, tenant-scoped, archives previous version to history, increments version. **Orphaned as of 2026-07-27** — its only caller (`PromptEditor.tsx`'s "Check & Save" button) was removed; see `System Docs/Known Gaps.md`. Route left in place, unreachable from any UI. |
| `/api/admin/prompt/check` | POST | Safety check for an entire system prompt (legacy, used by the old prompt save flow). Returns `{ pass, issues }`. **Orphaned as of 2026-07-27** alongside `/save` above, same reason. |

### Blocks

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/blocks` | GET | Returns active blocks (`id, title, type, body, is_default`) for the authenticated tenant. Filters `active = true`, ordered by type then title. Used for the Composer's existing-blocks context. |
| `/api/admin/blocks/[id]` | PATCH | Updates block `status`, `title`, `body`, `order`, or `type`. Validates status against `'active' \| 'disabled' \| 'deleted'`; `title` must be non-empty after trim (400 if empty); `order` must be an integer; `type` is validated against `BLOCK_TYPES` (400 on an invalid type). Keeps the legacy `active` boolean in sync with `status` so the Composer GET doesn't surface disabled or deleted blocks. Tenant-scoped, but not blindly by `authCtx.tenant_id` — first resolves the block's own `prompt_set_id` (unscoped lookup) through `resolveTenantForPromptSet` (July 2026), so a composer-family block still scopes correctly for a platform admin whose session tenant isn't SBL. |
| `/api/admin/blocks/save` | POST | Creates a new block (Composer draft confirmation flow + the manual New Block modal). **Body is the only required field**; `title` / `type` / `topic_id` are optional and stored null when omitted (400 only when `body` is missing). Tenant scope for the insert goes through `resolveTenantForPromptSet(body.prompt_set_id, ...)` (July 2026) — same composer-family override as `[id]` above. |
| `/api/admin/blocks/duplicate` | POST | Duplicates an existing block (`{ source_id }`). Resolves the source block's own `prompt_set_id` (unscoped lookup) through `resolveTenantForPromptSet` (July 2026) before the tenant-scoped duplicate, same composer-family override as `[id]`/`save` above. |
| `/api/admin/blocks/chat` | POST | Streaming chat route for the Composer. Accepts `{ type, topic, content, messages, documentContext?, existingBlocks? }`. Returns a Vercel AI SDK data stream. Thin consumer of `getCompiledComposerSystem` (`services/prompt/composer.ts`) — route owns only the ANTHROPIC_API_KEY guard + JSON parse. |

### Composer Conversations

**Not visitor-facing chat** — these back the Composer tool's own conversation-history drawer (the admin's saved chat threads with the prompt-building assistant), thin consumers of `services/prompt/conversations.ts`.

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/conversations` | GET | Lists the authenticated owner's conversations for their tenant, newest first (summary shape only — no `messages`). 401 on auth failure. |
| `/api/admin/conversations` | POST | Creates a conversation (lazy, on first send in the drawer). Body `{ title?, preview?, messages?, promptSetId? }` — `title` defaults to `'New conversation'` when omitted/blank. Writes a `CONVERSATION_CREATE` audit event. |
| `/api/admin/conversations/[id]` | GET | Hydrates one conversation (full row, including `messages` and `promptSetId`), owner+tenant scoped. 404 if not found or not owned by the caller. |
| `/api/admin/conversations/[id]` | PATCH | Updates a conversation — any subset of `{ title, preview, messages, promptSetId }` (client sends the full current `messages` array to append/replace the transcript). Writes a `CONVERSATION_UPDATE` audit event. |
| `/api/admin/conversations/[id]` | DELETE | Deletes a conversation, owner+tenant scoped. |

### Sage Parameters

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/sage-parameters` | GET | Returns all `sage_parameters` rows (`id, tenant_id, key, value, label, description, cta_label, url, open_as, embed_code, updated_at`) for the authenticated tenant, ordered by `key`. 401 when `getAuthContext()` fails. |
| `/api/admin/sage-parameters` | PATCH | Upserts a single parameter for the authenticated tenant. Accepts `{ key, label, description?, cta_label?, url?, value?, open_as?, embed_code? }` (strings except `embed_code` which may be string or null; `description` max 60 chars, `cta_label` max 20 chars; `open_as` one of `'new_tab' \| 'popup'`, default `'new_tab'`). Upsert uses `onConflict: 'tenant_id, key'` and stamps `updated_at` on write. 401 when `getAuthContext()` fails, 400 on invalid body. |
| `/api/admin/sage-parameters/[key]` | DELETE | Deletes the parameter matching `{ tenant_id, key }` for the authenticated tenant. 401 when `getAuthContext()` fails, 400 on missing key, 500 on Supabase error. |

### Prompt Sets

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/prompt-sets` | GET | Returns the authenticated tenant's `prompt_sets` rows as an **unwrapped** `PromptSet[]` (`id, tenant_id, label, description, status, is_composer_prompt, is_default, prompt_type_id, version, created_at, updated_at`), ordered `created_at desc`. **Excludes composer-family rows by default** (`.not('is_composer_prompt', 'is', true)`, added July 2026) — this is the ordinary tenant Settings screen; composer sets are managed exclusively from Platform Settings + Blocks, even for the SBL tenant itself. **`?include_composer=true` skips that exclusion** (added July 2026) for the one other caller that shares this route: the Composer editor's own "Building in" picker (`app/admin/prompt-builder/page.tsx`), which IS the composer-authoring context and needs to see composer-family sets — SBL's only `prompt_set` is one, so without this param that picker rendered nothing at all on SBL. Consumed unfiltered by the Settings `PromptSets` panel's fetch and with `include_composer=true` by the Composer picker's fetch. 401 on auth failure, 500 on DB error. |
| `/api/admin/prompt-sets` | PATCH | Upsert. Body `{ id?, label, description, status, prompt_type_id }`. With `id` → tenant-scoped update (404 if the id isn't in the tenant); without `id` → insert (`version`/`is_composer_prompt`/`is_default` from DB defaults). `version`/`is_composer_prompt`/`is_default`/timestamps are server-owned and never written. `prompt_type_id` can be assigned regardless of status — a draft may carry a type — it is only *required* non-null when `status === 'live'` (400 otherwise); when non-null it is validated to belong to the tenant's `prompt_types` (400 otherwise). Writes `PROMPT_SET_UPSERT` audit. |
| `/api/admin/prompt-sets/[id]` | DELETE | Deletes one set scoped to the session tenant (404 if not found). Returns `{ ok: true }`. Writes `PROMPT_SET_DELETE` audit. |

### Prompt Types

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/prompt-types` | GET | Returns `{ types, canMakePlatform }`. `types` (`id, key, name, description, sort_order`, ordered by `sort_order` (nulls last) then `name`) is the union of two queries, deduped by id: types assigned to the authenticated tenant via `prompt_type_tenants`, and platform-shared types (`prompt_types.is_platform = true`), visible to every tenant regardless of assignment. `canMakePlatform` reflects whether the current user is a platform admin (`requirePlatformAdmin()`), consumed client-side to gate the "make platform" option. Feeds the `PromptSets` panel's "Used as" type selector. 401 on auth failure, 500 on DB error. |
| `/api/admin/prompt-types` | POST | Creates a prompt type inline from the panel's "＋ New type…" affordance. Body `{ name, make_platform? }`. `key` is slugified from `name` (lowercase, non-alphanumerics → `_`, trimmed); `prompt_types` is a shared definition with no `tenant_id` write path here — find-or-create by `key` (keys are not globally unique; the first existing row wins), then assign the definition to the authenticated tenant via a `prompt_type_tenants` insert. `make_platform: true` sets `is_platform` on the definition (create or promote-on-find), but only when the current user is a platform admin (`requirePlatformAdmin()`, re-checked server-side — the client flag alone is never trusted). Returns the prompt-type row (201). 400 on missing/invalid name, 409 when the `prompt_type_tenants` unique constraint on `(prompt_type_id, tenant_id)` fires (already assigned to this tenant) — a non-409 failure after creating a brand-new definition rolls the orphaned `prompt_types` row back. |

### Tenant Settings

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/tenant-settings` | GET | Returns `{ chat_in_progress_idle_seconds, chat_active_idle_seconds, invite_gate_enabled, default_primer }` for the authenticated tenant. `invite_gate_enabled` is read from `tenants.settings` JSONB (default `true` when key absent). `default_primer` is read-only — echoed straight from the `tenants` row (see `System Docs/Database Schema.md`'s `tenants` row note), not an input field on this route. 401/404/500 as above. Consumed by `ChatThresholds` (Settings page) and `InvitesManager` (Invites page). |
| `/api/admin/tenant-settings` | PATCH | Accepts any subset of `{ chat_in_progress_idle_seconds, chat_active_idle_seconds, invite_gate_enabled }`. Threshold fields validated as before. `invite_gate_enabled` (boolean) is merged into `tenants.settings` JSONB via read-modify-write. **`default_primer` is not an accepted input field** — the PATCH body type has no such key — but the persisted-shape response it returns includes `default_primer` (re-selected from the `tenants` row alongside the updated columns), same read-only echo as the GET response above. 400 when no valid fields provided. |

### Platform Members (platform admin only)

All routes gate on `user.isPlatformAdmin` from `getCurrentUser()`. Audit rows written via `logEvent` (fire-and-forget).

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/platform/members/invite` | POST | Creates a members row with `status='invited'`, a generated token, and `expires_at` stamped `INVITE_TTL_DAYS` (14) out (`createMemberInvite`). Body: `{ tenant_id, invited_name?, email?, phone? }`. Optional email/phone are stored on the members row for contact-lock invites (used by `linkInvitedMember` for email-match activation via the webhook path). Looks up `tenants.domain` for the tenant and returns `{ token, member_id, invite_url }` where `invite_url = inviteUrlFor(token, domain)` → `'https://{domain}/invite/{token}'` (null when no domain configured). Backs `InviteMemberModal`. |
| `/api/platform/members/invite/resend` | POST | Regenerates the invite token for a member with `status IN ('invited','waitlist')`, resetting invite-tracking (`opened_at: null, opens: 0, revoked_at: null`) and stamping a fresh `expires_at` so the new link starts clean. Setting `status='invited'` on update promotes a waitlist member. Body: `{ member_id }`. Returns `{ token }`. |
| `/api/platform/members/invite/[memberId]` | GET | Returns the live `InviteLink` view model (`toInviteLink`) for the member drawer's on-open refetch. 404 if the row or its token is missing. |
| `/api/platform/members/invite/[memberId]` | DELETE | Hard-deletes a members row that has no linked users row (`user_id IS NULL`). Writes `MEMBER_HARD_DELETED` audit before delete. Guards against deleting rows that already have a users row. Returns 204. Distinct from the soft revoke below — this permanently removes the row. |
| `/api/platform/members/invite/[memberId]/revoke` | POST | Soft-revokes the invite: stamps `revoked_at` (does not delete the row). Refuses once `used_at` is set (409 — already accepted). Writes `MEMBER_INVITE_REVOKED` audit; returns the updated `InviteLink`. The token then 410s at `GET /invite/[token]` and is rejected by `validateMemberToken`/`acceptInvite`. |
| `/api/platform/members/roles` | PATCH | Updates role for one or more tenant memberships of a given user. Body: `{ user_id, changes: [{ tenant_id, role }] }`. Validates role against `owner\|admin\|member\|viewer`. Sequential updates; returns 207 with `failed_tenant_ids` on partial failure. One `MEMBER_ROLE_UPDATED` audit per change. |
| `/api/platform/members/status` | PATCH | Bulk status change across all memberships of target users. Body: `{ user_ids: string[], status }`. `PROTECTED_STATUSES = {deleted}` — never overwritten. Filters eligible memberships, bulk updates, one `MEMBER_STATUS_UPDATED` audit per affected row. |
| `/api/platform/members/[userId]` | DELETE | Hard-deletes a users row. DB cascade removes members, chat_sessions, etc. Writes `MEMBER_HARD_DELETED` audit before delete. 204 on success. |

**Tenant-admin mirrors:** `/api/admin/members/invite`, `/api/admin/members/invite/resend`, `/api/admin/members/invite/[memberId]` (GET/DELETE), and `/api/admin/members/invite/[memberId]/revoke` (POST) mirror the platform routes above one-for-one, scoped to the authenticated admin's own tenant via `getAuthContext()` (`.eq('tenant_id', authCtx.tenant_id)` on every query) instead of the `isPlatformAdmin` gate. Consumed by `app/admin/members/page.tsx` (`inviteApiBase="/api/admin/members"`).

**Retired:** `/api/admin/invites` (GET, POST) and `/api/admin/invites/[id]` (DELETE) are deleted. `/api/heirloom/invites/use` is deleted.

### Platform Settings → Composer Prompt + Tenant Prompts (platform admin only)

Backs the `/platform/settings` page. All routes gate on `getCurrentUser().isPlatformAdmin` (403 else; the `(platform)` layout already redirects non-admins, this is defense-in-depth).

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/platform/prompt-sets` | GET | Cross-tenant superset of prompt sets, now the full enriched row (not just the old lightweight Master Prompt picker shape) — `is_composer_prompt`, `is_default`, `prompt_type_id`, `version`, timestamps, plus derived compile meta (`block_count`/`last_compiled_at`/`compiled_version`), plus camelCase `tenantId`/`tenantName` aliases for back-compat. Sorted by tenant name then label. Backs both the Composer Prompt list (filtered client-side to `is_composer_prompt === true`) and the Tenant Prompts card (unfiltered). |
| `/api/platform/prompt-sets` | PATCH | Cross-tenant upsert. Body `{ id?, tenant_id?, label, description, status, prompt_type_id, is_composer_prompt? }`. With `id` → update (any tenant; `is_composer_prompt` may not be supplied here — 400 if it is). Without `id` → insert; `is_composer_prompt: true` is accepted **only as the literal boolean `true`** (July 2026, UK-4) — when present, `tenant_id` is ignored and hardcoded to the SBL/platform tenant (the create modal has no Tenant field), and `status` is forced to `'draft'` regardless of what's supplied. A composer set may still carry a `prompt_type_id` like any ordinary set — the flag is a pure category marker, unrelated to type. Writes `PROMPT_SET_UPSERT` audit (includes `is_composer_prompt` in metadata). |
| `/api/platform/prompt-sets/[id]` | DELETE | Cross-tenant delete, no confirmation beyond the client modal — no server-side guard against deleting a live, default, or composer-family set. Writes `PROMPT_SET_DELETE` audit. |
| `/api/platform/settings/master-prompt` | GET | Returns `{ promptSetId }` — the `prompt_sets` row with `is_composer_prompt = true AND status = 'live'` (or null). Read-only as of July 2026 (composer-family work) — see `System Docs/Known Gaps.md` for the retired `PUT`. |

### Heirloom Invites

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/heirloom/invites/accept` | POST | Accepts an invite token for the currently signed-in Clerk user. Body: `{ token: string }`. Requires Clerk session (401 if not signed in). Resolves the Supabase `users.id` for the clerk_id; calls `acceptInvite(token, clerkUserId, supabaseUserId)` from `services/members`; writes `MEMBER_INVITE_ACCEPTED` audit event. Returns `{ ok: true }` on success. Called by `ChatProvider` on the false→true `isSignedIn` transition when the visitor arrived with a valid `?invite=TOKEN`. |
| `/api/heirloom/invites` | POST | Added 2026-08-10 (invites-collaboration-modal). **No longer called by the UI as of reusable-story-invite-links, same day** — `ChatHero.tsx`'s magic-link creation was repointed to `/api/heirloom/story-invites` below; this route is left in place, untouched, and still functions standalone (its own test file still passes), but is now orphaned in practice. Member-facing collaborator-invite creation, backing `SidebarV2`'s per-story invite icon (`InviteCollaboratorsModal.tsx`). Distinct identity boundary from the admin/platform invite routes: resolves the caller via `getCurrentUser()` + a direct `members` lookup by `tenant_id=HEIRLOOM_TENANT_ID` + `clerk_id`, never `getAuthContext()` (that's the `tenant_users`/admin boundary — wrong identity model for an end-customer inviting someone to their own story). 401 with no Clerk session; 403 when the caller has no `members` row. Body: `{ primer?: string, story_id?: string }` — no invited_name/email/phone (this modal is a shareable "anyone with the link can join" magic link, unlike the admin invite form). Calls `createMemberInvite` with those args; `primer` falls back to `tenants.default_primer` when empty, same as the admin routes. `story_id` is **not persisted as a real relationship** — recorded only in the resulting `MEMBER_INVITE_CREATED` audit event's `metadata.story_id` as a provisional bridge (see `services/members/members.ts`'s `createMemberInvite` doc comment). This single-use-per-row mechanism is exactly why it was replaced: three different collaborators can't share one `members` row. Returns `{ token, member_id, invite_url }`, same shape as `/api/admin/members/invite`. |

### Story Invite Links

Reusable-story-invite-links (2026-08-10) — a durable, multi-person invite
link per story (`story_invite_links`, see `System Docs/Database Schema.md`),
deliberately a wholly separate mechanism from the single-use `/api/heirloom/
invites*` routes above and from the admin `/api/admin/members/invite*`
routes: no shared table, no shared service function, no shared code path.
Backed by `services/crm/story-invites.ts`.

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/heirloom/story-invites` | POST | Fetches-or-creates (`reset: false`/omitted) or rotates (`reset: true`) the one active invite link for a story — backs `InviteCollaboratorsModal.tsx`'s magic link via `ChatHero.tsx`. Identity resolution mirrors `/api/heirloom/invites`: `getCurrentUser()` + a direct `members` lookup by `tenant_id=HEIRLOOM_TENANT_ID` + `clerk_id` (401/403). Body: `{ story_id: string, primer?: string, reset?: boolean }`. Enforces story ownership server-side (`artifacts.user_id` must match the caller — 404 otherwise), independent of the sidebar's own decision not to hide the Invite/Delete controls from non-owners in V1. Without `reset`, returns the story's existing active link unchanged if one exists (the DB's partial unique index on `story_id WHERE revoked_at IS NULL` only allows one); with `reset: true`, revokes the current link (stamping `revoked_at`, never mutating a token in place) and inserts a fresh one. Default `expires_at` is 7 days out — a fixed default, no UI to change it in V1. Returns `{ token, story_id, primer, expires_at, invite_url }`. **As of invite_modal_updates (2026-08-10), `ChatHero.tsx` no longer calls this on modal open** — see the Known Gaps entry below; it fires only from an explicit Create or Reset link click. |
| `/api/heirloom/story-invites` | GET | Added invite_modal_updates (2026-08-10). Query: `?story_id=...`. Same identity + ownership gating as POST (401/403/404). Backs `InviteCollaboratorsModal.tsx`'s "Existing members" roster — calls `listStoryCollaborators` (`services/crm/story-invites.ts`), which joins `artifact_subscribers` (scoped to the story) to `members` (scoped to the tenant), two plain queries merged in application code rather than an embedded join, mirroring `listStories`' own pattern. No memory count in the response — see the Known Gaps entry below for why. **`active_link` added invite-modal-restore-on-open (2026-08-11):** the same response now also carries `active_link: { token, primer, invite_url } \| null` — `getActiveStoryInviteLink` (`services/crm/story-invites.ts`), the same `tenant_id` + `story_id` + `revoked_at IS NULL` lookup `createOrGetActiveStoryInviteLink` already does internally, but read-only (no create-if-missing fallback), reusing ownership already confirmed by the `listStoryCollaborators` call above rather than re-checking it. `invite_url` is built the same way POST's is (`https://{tenants.domain}/join/{token}`, `null` if the tenant has no domain). Lets `ChatHero.tsx` restore the real link/primer when reopening the modal for a story that already has one, instead of always showing "Not created yet" — see `System Docs/Known Gaps.md`. Returns `{ collaborators: [{ memberId, name, email, joinedAt }], active_link }`. |
| `/api/heirloom/story-invites` | DELETE | Added invite_modal_updates (2026-08-10). Body: `{ story_id: string }`. Same identity + ownership gating as POST. Revokes the story's active link (`revokeStoryInviteLink`) **without** inserting a replacement — distinct from POST's `reset: true`, which revokes and immediately re-creates. Backs the invite modal's invalidation warning: changing the story picker or the Custom Greeting while a link is live, once the warning's Continue is clicked, calls this so the magic-link row genuinely drops back to "Not created yet" server-side too, not just in the UI. Returns `{ ok: true }`; idempotent (revoking with nothing active is not an error). |
| `/api/heirloom/story-invites/accept` | POST | Accepts a story invite token for the currently signed-in Clerk user. Body: `{ token: string }`. Requires Clerk session (401 if not). Calls `acceptStoryInvite(token, clerkUserId, supabaseUserId, tenantId)` (`services/crm/story-invites.ts`), which branches on whether the caller already has a `members` row for this tenant: an existing member gets only an `artifact_subscribers` grant; a brand-new person gets a fresh `members` row inserted directly as `status='active'` (`source='story_invite'`, primer copied from the link) plus the same grant. Returns `{ ok: true, story_id, story_title, is_new_member }`. Called by `chatStore.tsx` from **two** trigger points, not one — the false→true `isSignedIn` transition (brand-new signup, same shape as `/api/heirloom/invites/accept`'s own trigger) AND a mount-time check for a visitor who was already signed in when they arrived (an existing Heirloom member opening the link while already logged in never crosses a sign-in transition, so without this second trigger the accept call would simply never fire for that case — see `chatStore.tsx`'s own doc comment). **Client-side diagnostic logging added 2026-08-10 (PR #341)** covers both triggers and this call end-to-end — see the `chatStore` row in `System Docs/Public Site.md`; added to debug a live gap (accepted invite not resulting in the story appearing in the member's account) that PR #341 itself did not root-cause, but four independent follow-up fixes (PRs #343, #344, #346, #348) did, closing it out — see `System Docs/Known Gaps.md`. **This route can now also be raced by the `user.created` webhook itself (PR #351, 2026-08-11)** — see this file's `/api/webhooks/clerk` row and `System Docs/Known Gaps.md` — since both ultimately call the same `acceptStoryInvite()`, this route's own behavior when it loses that race is unchanged: it still finds the row `acceptStoryInvite` already created and takes the existing-member branch. |
| `/join/[token]` | GET | Public, unauthenticated redirect — the story-invite-link counterpart to `/invite/[token]` (which reads `members.token`; this reads `story_invite_links.token` — separate table, separate route, no shared code). 404 if the token doesn't exist; 410 if revoked or past `expires_at` (enforced here, unlike `/invite/[token]`'s not-yet-enforced `expires_at`). Writes `STORY_INVITE_LINK_OPENED` audit, then 302s to `/?join=TOKEN`, which `app/heirloom/page.tsx` reads as its own independent branch alongside (never merged with) the existing `?invite=` branch. Never rewritten under a product segment on any host — `isJoinPath` in Middleware, mirroring `isInvitePath`'s exact treatment (added in a post-merge fix; the route initially shipped without this guard, which would have 404'd every hit on `heirloom.2bl.ai` — see `System Docs/App Structure and Routing.md`). |

### Content / Assets

| Route | Method | Purpose |
|-------|--------|---------|
| `/api/admin/assets/upload` | POST | Multipart upload for documents (PDF, DOCX, TXT). Extracts text via Anthropic (PDF) or mammoth (DOCX) or direct Buffer read (TXT), inserts a `content` row with `type: 'document'`, uploads the original binary to the Supabase Storage `assets` bucket at `{tenant_id}/{content_id}/{filename}`, and updates the content record with the storage path.
