# Pages

## Pages

Admin page routes under `app/admin/` and platform-admin page routes under
`app/(platform)/platform/` (own section below). Each page owns its route
header and section scaffolding; data fetching lives in server components or
page-local client components.

| Page | File | Purpose |
|------|------|---------|
| Settings | `app/admin/settings/page.tsx` | Tenant configuration. Mantine `Accordion` with five panels in order: Parameters (`SageParameters`), Prompt Sets (`PromptSets`), Chat Thresholds (`ChatThresholds`), Invite Gate (`InviteGate`), Appearance (`Appearance`). |
| Members | `app/admin/members/page.tsx` | Platform-admin member management across all tenants. Server component — queries signed-up users (with embedded members) + invited-only members rows (user_id IS NULL, status in invited/waitlist); fetches `tenants.domain` in both queries and the tenants list; passes combined UserRow[] (with `Membership.tenantDomain`) to `MembersList`. Sidebar nav entry: **Members** at `/admin/members`. **Retired**: `app/admin/invites/` (deleted — invite management moved here). |
| Session detail | `app/admin/sessions/[id]/page.tsx` | Not previously documented. Server component at `/admin/sessions/[id]` — the Inbound Chats table's detail drill-in. `getAuthContext()`-scoped fetch of one `chat_sessions` row (`notFound()` on auth failure or missing row) plus the tenant's idle-threshold settings for status derivation (`deriveSessionStatus`). Renders the full transcript with `parseBookingCards` stripping marker syntax into readable booking cards; a copy-transcript button (`CopyTranscriptButton`) formats the conversation as plain "Visitor:/Sage:" text. **Platform-admin-only debug pills** (`showDebugMarkers`, gated on `getCurrentUser().isPlatformAdmin`) additionally surface the raw stripped marker brackets (`[NAME:]`/`[EMAIL:]`/`[PHONE:]`/`[BOOKING:]`/`[ACCOUNT_CREATE]`) inline per message — tenant admins see the page without them. Backs the admin session-transfer action (`System Docs/API Routes.md`'s `/api/admin/sessions/[id]/transfer`). |
| Inbound Chats | `app/admin/page.tsx` | Tenant admin's home/dashboard route (`/admin`). Not previously documented. Server component — `getAuthContext()` then fetches `getInboundChats(tenant_id)` and `getTtftTrend(tenant_id)` (`services/crm/inbound`) in parallel; both fall back to empty arrays on auth failure rather than erroring the page. Renders a sticky header ("Inbound Chats — Sage conversation history") over a scrollable body containing `InboundChartsDashboard` (charts, fed `rows` + `ttftTrend`) and `InboundChatsTable` (the session list). Header/scroll-body split mirrors the Blocks and platform Members pages. `dynamic = 'force-dynamic'`. |
| Composer | `app/admin/prompt-builder/page.tsx` | Not previously documented, despite being referenced elsewhere in `System Docs/API Routes.md`. Fully client-side (`'use client'`) chat-driven block-drafting tool, distinct from the Blocks screen's inline draft flow. Streams against `/api/admin/prompt-chat` (see `System Docs/API Routes.md`); on a "done" JSON payload embedded in the stream, parses out draft block cards (title/content/suggested type/topic) for review before saving via `/api/admin/blocks/save`. Owns its own conversation history drawer (`ConversationSidebar`, backed by `/api/admin/conversations*`) and a "Building in" `PromptSetSelect` (fetches `?include_composer=true` so composer-family sets are visible here, unlike the ordinary tenant Settings picker). Supports document upload (`/api/admin/assets/upload`) that auto-triggers an analysis turn, per-card safety check before save (`/api/admin/prompt/compile/check`) with a "save anyway" bypass, and honors a `?promptSet=<id>` deep link from elsewhere in the admin (e.g. the "Open in Composer" action). `dynamic = 'force-dynamic'` (for `useSearchParams`). |
| Assets | `app/admin/prompt-studio/assets/page.tsx` | Not previously documented. Server component — tenant-scoped `content` rows where `type='document'`, newest first, rendered by `AssetsTable`. Same header/error-fallback shape as History and Prompt (Studio) below (title bar + "Unable to load" empty state on auth failure). `dynamic = 'force-dynamic'`. |
| History | `app/admin/prompt-studio/history/page.tsx` | Not previously documented. Server component — tenant-scoped `chat_sessions` rows where `session_type='composer'` (i.e. Composer chat sessions, not visitor Sage sessions), newest first, joined to `blocks(title)` via `block_id`, rendered by `HistoryTable`. Same auth-failure fallback pattern as Assets. `dynamic = 'force-dynamic'`. |
| Prompt (Studio) | `app/admin/prompt-studio/prompt/page.tsx` | Not previously documented. Server component — reads the tenant's single `compiled_prompts` row (content/version/updated_at, no `.order()` — assumes one row) plus all active `blocks` bodies, passed to a client `PromptPreview` component. Distinct from `app/admin/prompt/page.tsx` below — this is the Prompt Studio nav tab's read-oriented preview; the other is the legacy standalone editor. `dynamic = 'force-dynamic'`. |
| Prompt (legacy editor) | `app/admin/prompt/page.tsx` | Not previously documented. Server component — reads the tenant's highest-version `compiled_prompts` row plus up to 20 rows of `compiled_prompts_history`, falling back to `DEFAULT_SYSTEM_PROMPT`/version 0 on no data or auth failure. Renders `PromptEditor`, the legacy manual save/check flow — see `System Docs/Known Gaps.md`'s note that `PromptEditor`'s "Check & Save" button (and the `/api/admin/prompt/save`+`/check` routes it called) was removed 2026-07-27; this page itself remains reachable but its save path is now orphaned. `dynamic = 'force-dynamic'`. |
| Blocks | `app/admin/prompt-studio/blocks/page.tsx` | Server component — fetches all non-deleted blocks for the tenant (including `order`) and renders `BlocksTable`. **Prompt-set picker**: `getPromptSets()` queries the `prompt_sets_with_compile_meta` VIEW (not the raw `prompt_sets` table — same view the tenant-Settings screen's `GET /api/admin/prompt-sets` reads, joined against `compiled_prompts` by `prompt_set_id`), returning each set's `prompt_type_id` (UUID, informational only), plus the derived `lastCompiledAt`/`compiledVersion` (compiled_prompts.updated_at/version for that set — see Compile & Publish below). The active set scopes the blocks query by `blocks.prompt_set_id === activeSet.id` (the set's own row id, never `prompt_type_id` — that field plays no part in the blocks filter). Status uses lowercase `'live'/'draft'` (DB constraint); `PromptSetSelect` / `BlocksOverview` capitalize for display. `PromptSetSelect` (July 2026 — moved to `components/admin/prompt-studio/PromptSetSelect.tsx`, alongside its shared types/`familyOf` logic in `promptSet.ts`) is no longer Blocks-only: the Composer editor's "Building in" control (`app/admin/prompt-builder/page.tsx`) is the exact same component, passed `label="Building in"` plus `onSelect`/`onCreate` props Blocks doesn't use (picking a set there sets local state instead of navigating; an inline "New prompt set…" form is Composer-only). The former `components/admin/prompt-builder/PromptSetPicker.tsx` — a hand-duplicated copy in plain CSS Modules — is retired. **Row/card affordances (desktop `BlockRow` + mobile `BlockCard`):** inline `Order` field (Mantine `NumberInput`, blur-to-save via `PATCH /api/admin/blocks/[id]` with `{ order }`; duplicate-order check fires a red notification and aborts); inline title rename (double-click title → `TextInput`, Enter/blur commits via `PATCH { title }`, Escape cancels); duplicate confirmation `Popover` (Duplicate / Cancel + "Don't ask again" checkbox persisted to `localStorage` key `block-admin:skip-dup-confirm`; skips popover on subsequent clicks when checked); clipboard copy of block body (`IconClipboard` → `navigator.clipboard.writeText`, 2-second `IconCheck` feedback). **Dates column (desktop only, July 2026):** replaced the old "Updated X ago" line that sat under the title — `BlockRow`'s Dates cell now shows both `Created {formatShortDate}` (absolute, e.g. "Jan 5") and `Updated {formatRelativeTime}` stacked, both `suppressHydrationWarning` (`formatShortDate`, `services/shared/time.ts`, resolves against the runtime's local zone same as the relative one, so a block created near local midnight can render a different calendar day server- vs. client-side). **Sortable column headers (`BlocksTable.tsx` + `sortBlocks.ts`, July 2026):** Title, Type, and the Dates column's "Last updated" label are each a `SortLabel` button — click to sort ascending, click again to flip to descending, click a different header to take over at that field's own default (descending for the date field, ascending otherwise); default state is `sortBy = null` (the table's original/authored order). Sort is applied client-side after search/type/status filtering (`sorted = sortBlocks(filtered, sortBy, sortDir)`), and every "currently visible" derived value (`maxVisibleTokens`, `allExpanded`, `filteredSelectedCount`, select-all, expand-all, and both the desktop table body and the mobile card stack) reads `sorted` rather than `filtered` — a pure reorder, so none of those values differ from their pre-sort equivalents, only their order does. No sort-order persistence (resets to unsorted on reload) and no reset-on-prompt-set-switch effect — sort state behaves like `selectedIds`/`expandedIds`/the search query, none of which are explicitly cleared when switching sets either (only `typeFilter`/`statusFilter` effectively reset, and that's a side effect of `PromptSetSelect` navigating to a URL stripped down to just `?set=`, not a reset effect inside `BlocksTable`). Type sorts by `ORDERED_TYPES` (compile order), not alphabetically. Mobile cards have no header UI to change the sort but do render in the same `sorted` order as desktop. **Edit drawer/sheet (`BlockEditForm`, edit mode):** editable Title `TextInput` at top (blur/Enter commits via `PATCH { title }`, Escape reverts; drawer header title updates reactively from items state); clipboard copy icon in the action row (right-aligned, same 2-second feedback). **Compile & Publish (`PublishButton` + `CompilePublishModal`, both `app/admin/prompt-studio/blocks/` and `components/admin/prompt-studio/`):** three-stage modal — Compile (loading) → Review (read-only compiled output, Copy/Download/Cancel/Publish→) → Describe (July 2026 — a required one-line `Summary` (≤72 chars, `services/prompt/release-note.ts`'s `SUMMARY_MAX`), optional `Why`, and an auto-derived "changed since" chip list of blocks edited after the set's `lastCompiledAt`; `⌘↵`/`Ctrl↵` submits). The compile POST (`/api/admin/prompt/compile`) fires only from stage 3, carrying `{ prompt_set_id, note }`; stage 2's "Publish" only advances to stage 3. The pending version shown in both stages (`Will publish as vN` / `Publish vN`) is `compiledVersion + 1` (compiled_prompts.version for this slot, sourced from the same view) — **not** `prompt_sets.version`, which is set once at row creation and never incremented again, so it silently drifts from the real publish history (observed in prod: a tenant's `prompt_sets.version` sitting several versions behind its `compiled_prompts.version`). |

## Platform Pages

Page routes under `app/(platform)/platform/` — platform-admin only, gated by
the `(platform)` layout, distinct from the tenant-scoped `app/admin/` pages
above. Not previously documented anywhere in this file.

| Page | File | Purpose |
|------|------|---------|
| Tenants | `app/(platform)/platform/admin/page.tsx` | **Filename/content mismatch worth knowing**: despite the `admin` path segment, this renders the **Tenants** list (component `PlatformTenantsPage`), routed at `/platform/admin`. Defense-in-depth re-check of `isPlatformAdmin` (redirects non-admins to `/admin`, unauthenticated to sign-in) even though the `(platform)` layout already gates this, since the page runs a privileged cross-tenant `tenants` read. Renders `TenantList` with every tenant's `id, parent_id, name, slug, type, domain`, grouped by parent. |
| Members | `app/(platform)/platform/members/page.tsx` | Platform-admin cross-tenant member management, mirroring `app/admin/members/page.tsx`'s data-fetching pattern but rendered inside `PlatformShell`. Three parallel queries: signed-up users with embedded `members` (joined to inviter + tenant), invited-only rows (`user_id IS NULL`, status `invited`/`waitlist`), and **orphaned rows** (`user_id IS NULL`, status not invited/waitlist — a data-integrity gap per `System Docs/Known Gaps.md` that neither of the other two queries would otherwise surface in the UI at all). Renders `MembersDashboard` + the shared `MembersList` component with `inviteApiBase="/api/platform/members"`. Same header/scroll-body split as `app/admin/page.tsx`. `dynamic = 'force-dynamic'`. |
| Products | `app/(platform)/platform/products/page.tsx` | Placeholder — static "Coming soon" page, no data fetching. |
| Settings | `app/(platform)/platform/settings/page.tsx` | Client component (`'use client'`) — Composer Prompt management (Accordion panel listing composer-family prompt sets, i.e. `is_composer_prompt=true`, fetched unfiltered from `/api/platform/prompt-sets` then filtered client-side) plus an "Add New" modal that PATCHes a new draft composer set. **Read-only as of July 2026** — there's no Select/Save/Revert here anymore; the only way to make a composer set live is Compile & Publish on the Blocks screen (each row's Edit pencil routes to `/admin/prompt-studio/blocks?set=<id>`). Also renders `TenantPrompts` (the cross-tenant prompt-set management card) below the accordion, backed by `System Docs/API Routes.md`'s "Platform Prompt Types & Tenants" and "Platform Settings" sections. |
| Usage | `app/(platform)/platform/usage/page.tsx` | Placeholder — static "Coming soon" page, no data fetching. |
