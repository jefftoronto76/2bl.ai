Guardrail counter — Blocks

A compact, always-visible meter that tells an admin how many active guardrail blocks the current prompt set has, against a best-practice ceiling of five.

Screen
Prompt Studio · Blocks (app/admin/prompt-studio/blocks)
Stack
Mantine @mantine/core 7.17.8 · buildAdminTheme tokens
Scope
One new indicator in the prompt-set summary. No new endpoints, filters, or data model.
Status
Spec + component design. Not yet implemented — this document is the port target.

Why

Guardrail blocks compound. Past five, they start to contradict each other and dilute the ones that matter — reliability drops rather than climbs. The Blocks screen already shows a token donut and per-type filter counts, but nothing tells an admin they've crossed the guardrail best-practice line. This surfaces that one number where they're already reading counts, and nudges them back under the line before they publish.

Best-practice ceiling is 5. Five is the soft maximum, not a hard block — the admin can still save and publish past it. The counter informs and nudges; it never prevents.

The rule

Count = active guardrail blocks in the current prompt set. Disabled / archived guardrails do not count. The count drives one of three tones:

CountToneReads asMessage
0–4Neutral (gray)Within best practiceGuardrails · 3 / 5
5Warning (yellow)At the ceilingGuardrails · 5 / 5 + “At the recommended limit”
6+Error (red)Over best practiceGuardrails · 6 / 5 + “Reduce to improve reliability”

Current sample data: “Sage — Production” has one active guardrail, so the live default state is a neutral 1 / 5.

Component design

A single self-contained pill — shield icon · “Guardrails” · N / 5 — built on the Mantine Badge (variant="light"), the same primitive the type badges already use. Tone is the badge color prop (gray → yellow → red); nothing else about the shape changes. At the warning and error tones a short helper line sits beside the pill (never inside it) so the pill itself stays a fixed, scannable size.

Anatomy

  • Icon — a shield reads “guardrail” at a glance; it flips to an alert triangle only in the over state, so red + triangle together carry the strongest signal.
  • Label + count — Guardrails in body weight, the N / 5 in DM Mono to match every other count on the page (token totals, filter counts, filtered / total).
  • Helper line — appears only at 5 and 6+, one short clause, dimmed at warning and red at error.
  • No new colors — gray / yellow / red are Mantine theme scales already in the admin palette; the red matches the donut’s existing over-limit red (--mantine-color-red-7).

Placement

The counter lives in the prompt-set summary at the top of the page, so it is visible without scrolling in both states of that summary:

  • Summary expanded — the pill sits in the left summary card’s stat area, on its own row directly beneath “Active blocks”, reading identity → counts → guardrail health.
  • Summary collapsed — the pill joins the one-line summary bar next to “N active blocks” and “N tokens”, so it never disappears when the summary is hidden.

It is a status indicator, not a filter. Clicking it does nothing by default; a future enhancement (below) could make it filter the table to guardrails.

Data logic

Derived from state already in the screen — no new fetch. The count is active guardrails scoped to the set in view:

// blocks-screen.js — inside Blocks(), alongside the existing counts.
// inSet = items already scoped to the current prompt set.
const GUARDRAIL_LIMIT = 5
const guardrailCount = inSet.filter(
  (b) => b.type === 'guardrail' && b.status === 'active'
).length
const guardrailTone =
  guardrailCount > GUARDRAIL_LIMIT ? 'error'
  : guardrailCount === GUARDRAIL_LIMIT ? 'warning'
  : 'neutral'

Production note: the ceiling of 5 is a UI constant here. If it should be configurable per tenant later, resolve it from prompt-set settings server-side rather than hard-coding — but ship the constant first.

Component sketch (Mantine)

A small presentational component; tone → { color, Icon, hint }. Illustrative, not final code:

const GR = {
  neutral: { color: 'gray',   Icon: IconShieldHalf,    hint: null },
  warning: { color: 'yellow', Icon: IconShieldHalf,    hint: 'At the recommended limit' },
  error:   { color: 'red',    Icon: IconAlertTriangle, hint: 'Reduce to improve reliability' },
}

function GuardrailMeter({ count, limit = 5, tone }) {
  const { color, Icon, hint } = GR[tone]
  return html`
    <${M.Group} gap="xs" align="center" wrap="nowrap">
      <${M.Badge} color=${color} variant="light" radius="xl" size="lg"
        leftSection=${html`<${Icon} size=${14} />`}>
        Guardrails ${count} / ${limit}
      <//>
      ${hint && html`<${M.Text} size="xs" c=${tone === 'error' ? 'red.7' : 'dimmed'}>${hint}<//>`}
    <//>`
}

QA checklist

  • Pill is visible at the top of Blocks without scrolling, in both expanded and collapsed summary states.
  • Count reflects only active guardrails — toggling a guardrail’s switch off decrements it immediately.
  • Disabled and non-guardrail blocks never affect the number.
  • 0–4 renders gray, 5 renders yellow with “At the recommended limit”, 6+ renders red with the reduce message.
  • Switching prompt sets recomputes the count for the newly selected set.
  • Count digits use DM Mono, matching the page’s other counts.
  • Contrast passes at all three tones; the pill doesn’t wrap or resize between states.

Out of scope / follow-ups

  • Click-to-filter — tapping the pill could filter the table to guardrails. Propose separately.
  • Per-tenant limit — configurable ceiling from prompt-set settings; ship the constant first.
  • Publish-time nudge — an optional confirmation when publishing a set that is over the limit.
